Loop · Repo-as-mailbox

The work advances. The record accumulates.

Work flows clockwise around the ring — solid arcs. Every pass writes durable state back to the one shared record — dashed spokes.

Why a loop

The last step feeds the first

  • A verdict becomes the next task — the ring never idles on a finished step
  • AWAITING_FOUNDER stops both pollers until a human decides
  • Nothing counts as done until it is in the record

The hub is the point

State outlives the agents

  • Every write-back is a commit — the ring's memory is git, not chat
  • STATE.md names who waits on whom
  • Swap either agent mid-flight; the record stays
