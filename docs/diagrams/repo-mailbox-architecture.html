Architecture · Repo-as-mailbox

Stop wiring agents. Start mailing them.

Two agents, one repo mailbox — commit-only messages, marker-based polling, zero human relay.

Audit trail

Every message is a commit

  • One timestamped, append-only file per message — never edited by the other side
  • STATE.md names who waits on whom; a stop state silences both pollers
  • The history of the build is the git log — nothing lives only in chat

Zero-token polling

Idle costs nothing

  • A poll compares one marker hash against origin/main
  • Unchanged → identical bytes → the scheduler suppresses the agent run
  • No tokens burn while waiting on a human decision

The payoff

The implementer is a commodity

  • Swap the tool with a one-line change in the coordinator
  • The mailbox, state machine, and verification gates never move
  • Field-validated end-to-end in production, 2026
