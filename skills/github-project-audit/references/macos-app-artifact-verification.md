# Native macOS App Artifact Verification — Extension to Layer 4/5

Added 2026-10-11 from a live audit of a shipped, signed and notarized macOS utility.

Any `.app`/`.dmg` audit settles three claims — *signed? notarized? what can it reach?* Read all three off
the ARTIFACT. A README's word on them goes stale in both directions, and the DMG and the inner binary
carry **separate** signatures.

## 1. Signing and notarization
```bash
curl -sL -o app.dmg "https://github.com/OWNER/REPO/releases/download/TAG/NAME.dmg"
shasum -a 256 app.dmg                        # the one value a later user can re-check
codesign -dvvv app.dmg 2>&1 | grep -E 'Authority|TeamIdentifier|Timestamp|flags'
xcrun stapler validate app.dmg               # "The validate action worked!"
spctl -a -t open --context context:primary-signature -v app.dmg   # accepted / source=Notarized Developer ID
```
Mount read-only and repeat on the inner binary, then always detach:
```bash
mkdir -p mnt && hdiutil attach app.dmg -nobrowse -readonly -mountpoint mnt
BIN="mnt/App.app/Contents/MacOS/App"
codesign -dvvv "$BIN"                        # flags=0x10000(runtime) = hardened runtime
codesign -d --entitlements :- "$BIN"         # 0 bytes = no declared capability
lipo -info "$BIN"                            # vs "Apple silicon and Intel"
plutil -p mnt/App.app/Contents/Info.plist | grep -iE 'MinimumSystemVersion|CFBundleShortVersion'
hdiutil detach mnt
```
Tabulate claim against reading: Developer ID identity, hardened-runtime flag, notarization source,
`LSMinimumSystemVersion` vs "requires macOS N", architectures vs the README.

## 2. "No network / no analytics" — in this order
1. `otool -L "$BIN"` and `ls Contents/Frameworks` — **the linked libraries ARE the capability.** Only
   `/System/Library/...` and `/usr/lib/...` entries ⇒ no third-party SDK is present to phone home.
2. Entitlements. An empty dump (no `com.apple.security.*`) means *no declared capability*; it does **not**
   mean sandboxed. State which of the two you observed instead of implying the stronger one.
3. `strings -a "$BIN" | grep -iE 'https?://|analytics|api\.'` — the URL set, not the SDK set.
4. `nm -u "$BIN" | grep -iE 'URLSession|CFNetwork|socket|getaddrinfo'` — supporting, never decisive.

### The trap that inverts the verdict
`_CGSMainConnectionID` (CoreGraphics' window-server connection) matches a naive `connection|socket|network`
grep and exists in every AppKit app: a symbol grep alone reports a network-capable binary for a program
that cannot open a socket. Verify in the order above and quote which check carried the verdict.

## 3. What a build with no CI cannot prove
No workflow and no published checksum ⇒ the signature proves *who built it* and *that nothing changed
afterwards*, **not that the bytes came from the tagged source**. Report that as the residual gap, hand over
the sha256 you computed, and never phrase it as "verified build". Nor let a 4-day-old repo's watcher/star
ratio enter a verdict: the meaning of a ratio depends on its age.

## 4. Consent-shaped surfaces worth reading in the source
- A pasteboard watcher: does it honour `org.nspasteboard.ConcealedType` / `TransientType` /
  `AutoGeneratedType`, and does it refuse anything carrying `.string` or `.fileURL`? Saved copies should
  land `0600`, since what people copy can be private.
- A settings takeover (e.g. redirecting screenshots): it must save the user's previous values first,
  refuse to record its OWN values as "previous" after a crash, and restore on quit.
- Whether the feature ships **off by default** is part of the security answer, not a UX detail.
